# 23 — Glossary

Terms as used specifically within the EventFlow codebase and this documentation pack. CONFIRMED entries cite the schema/code source of the term; a small number of general industry terms are included for reader convenience and marked accordingly.

| Term | Definition |
|---|---|
| **Planner** | A registered subscriber account (`UserRole.PLANNER`), the primary paying user who creates and manages events. |
| **Admin** | An internal EventFlow support role (`UserRole.ADMIN`) with cross-subscriber visibility and owner-equivalent access to any event, minus deletion and payout-connection rights. |
| **Guest** | A person invited to a private event, represented by a `Guest` row; may or may not have a user account (guests never log in). |
| **RSVP token** | The unique, unguessable value on `Event.rsvpToken` that serves as the bearer credential for the shared public RSVP link. |
| **Invitation token** | The unique value on `EventInvitation.token`, a personalised (per-guest) bearer credential for a pre-filled RSVP link. |
| **Public slug** | `Event.publicSlug` — an immutable, URL-safe identifier generated once an event is made public, used in `/tickets/:slug`. |
| **isPublic** | The `Event` boolean flag that switches an event from the private RSVP flow into the public ticket-selling flow. |
| **Party / party member** | A named individual accompanying a primary guest (a "+1"), stored as a `GuestParty` row, distinct from the simple numeric `additionalGuestsCount`. |
| **Seating assignment** | A `SeatingAssignment` (for a `Guest`) or `PartySeatingAssignment` (for a `GuestParty` member) row linking a person to a specific table and, optionally, a specific seat. |
| **Layout object** | A freeform decor element (stage, bar, dance floor, etc.) placed on the venue canvas, represented by `LayoutObject`. |
| **Vendor** | A third-party supplier (caterer, photographer, etc.) tracked per event via the `Vendor` model. |
| **Product** | A sellable merchandise item on an event's shop (`Product` model). |
| **Order** | A purchase (merchandise or ticket, distinguished by `Order.kind`) moving through `PENDING → PAID/CANCELLED`. |
| **OrderKind** | The enum (`MERCHANDISE` \| `TICKET`) distinguishing what an `Order` is for, allowing one checkout/payment pipeline to serve both. |
| **Payout account** | An `EventPayoutAccount` row: one planner's connection to one payment processor for one currency. |
| **Platform fee** | EventFlow's percentage cut of a paid order, taken via the processor's own fee mechanism, configured via `PLATFORM_FEE_PERCENT` (merchandise) or `TICKET_FEE_PERCENT` (tickets). |
| **Stripe Connect** | Stripe's platform-payments product, used here (Express accounts) to let a planner receive USD/GBP payments directly, minus EventFlow's application fee. |
| **Paystack Subaccount** | Paystack's split-payment mechanism, used here for NGN payouts. |
| **Ticket type** | A purchasable tier on a public event (e.g. "General Admission"), represented by `TicketType`, with its own price, currency, and capacity. |
| **Ticket** | One issued, individually-scannable admission credential (`Ticket` model, unique `code`), created per unit purchased once an order is `PAID`. |
| **Check-in** | The act of marking a guest (`Guest.checkedIn`) or ticket (`Ticket.status = CHECKED_IN`) as arrived at the event, via manual action or QR scan. |
| **Needs Attention insight** | A computed-on-demand item (`Insight`, no persisted table) flagging something needing planner action (e.g. an unassigned VIP), generated by the insights module. |
| **Notification** | A persisted, in-app alert (`Notification` model) generated as a side effect of RSVP changes, vendor status changes, or paid orders. |
| **Admin bypass** | The mechanism by which `getOwnedEvent` grants an `ADMIN` user the same access to an event that its owner has, without a separate admin-only API. |
| **Admin audit log** | `AdminAuditLog` — a record of every mutation an admin makes on an event they don't own, written by the `auditAdminEventActions` middleware. |
| **Payment event** | `PaymentEvent` — a log row for every payment-processor callback received (success, failure, or expiry), independent of the resulting order status. |
| **Webhook** | An inbound HTTP callback from Stripe or Paystack notifying the API of a payment outcome, verified by cryptographic signature before being trusted. |
| **CUID** | "Collision-resistant Unique IDentifier" — the ID generation strategy (`cuid()`) used for every Prisma model's primary key in this schema. *(General term, included for reader convenience.)* |
| **Zod** | The TypeScript-first schema validation library used for all request body/query/params validation in `apps/api`. *(General term.)* |
| **Prisma** | The TypeScript ORM used to access PostgreSQL from `apps/api`. *(General term.)* |
| **PWA** | Progressive Web App — the installable-web-app capability EventFlow's frontend provides via a manifest and service worker. *(General term.)* |
